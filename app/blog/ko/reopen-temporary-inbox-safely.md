## 접근 권한을 잃지 않고 임시 받은편지함을 안전하게 다시 여는 방법

cleanorapi.com의 임시 받은편지함은 전체 이메일 주소가 포함된 직접 URL을 이용해 다시 열 수 있습니다. 실수로 탭을 닫았거나 브라우저를 다시 시작했을 때, 또는 짧은 가입 절차를 잠시 중단했다가 이어갈 때 유용합니다. 그러나 받은편지함을 “다시 연다”는 말은 삭제된 메일을 복구한다는 뜻이 아니며, 임시 주소가 비밀번호로 보호되는 영구 계정으로 바뀐다는 뜻도 아닙니다.

직접 링크 방식에서는 전체 이메일 주소가 사실상 단기 접근 정보 역할을 합니다. 주소를 아는 사람은 같은 경로를 만들 수 있습니다. 또한 수신된 메일은 최대 24시간만 보관된 뒤 자동 정리됩니다. 따라서 이 기능은 합법적이고 서비스 정책에 허용되며, 실패해도 큰 손실이 없는 짧은 작업에만 사용해야 합니다. 결제 내역, 신분 확인 문서, 업무 기밀, 개인 파일, 장기 계정 복구 메일을 받아야 한다면 비밀번호와 복구 수단이 있는 일반 이메일이 더 적절합니다.

### 직접 받은편지함 링크를 열면 일어나는 일

기본 URL 형식은 다음과 같습니다.

`https://cleanorapi.com/inbox/전체주소@현재지원되는도메인`

사이트에 표시된 주소를 사용자 이름 부분과 도메인까지 정확히 복사해야 합니다. 링크가 열리면 cleanorapi.com은 주소를 정규화하고 검증합니다. 형식이 올바르고, 현재 허용된 수신 도메인을 사용하며, 예약된 사서함 이름이 아닌 경우에만 주소가 서명된 브라우저 세션에 저장되고 받은편지함으로 이동합니다.

이 링크를 열면 해당 주소에 대해 새로운 24시간 세션 접근 기간이 시작됩니다. 동시에 같은 브라우저 세션에 저장되어 있던 기존 임시 주소는 새 주소로 교체됩니다. 다른 받은편지함에 필요한 정보가 있다면 다른 직접 링크를 열기 전에 먼저 확인해야 합니다. 탭을 두 개 사용하더라도 세션 저장값을 공유하면 현재 주소가 바뀔 수 있습니다.

직접 링크는 한 번 사용하고 폐기되는 비밀 토큰이 아닙니다. 같은 링크를 나중에 다시 방문하면 새 브라우저나 기존 세션에 주소를 다시 등록할 수 있습니다. 이 편리함이 바로 중요한 개인정보 보호 한계입니다. 전체 주소를 알게 된 사람도 같은 임시 받은편지함에 접근할 가능성이 있다는 전제로 다뤄야 합니다.

### 세션 갱신과 삭제 메일 복구는 다릅니다

사용자가 자주 혼동하는 세 가지 대상을 구분하면 다음과 같습니다.

| 대상 | 다시 열어서 할 수 있는 일 | 다시 열어도 할 수 없는 일 |
| --- | --- | --- |
| 브라우저 세션 | 주소를 다시 등록하고 새 접근 기간 시작 | 삭제된 쿠키를 복원하거나 최초 생성자를 증명 |
| 받은편지함 주소 | 같은 수신 주소로 브라우저를 이동 | 비밀번호가 있는 개인 계정으로 전환 |
| 저장된 메일 | 보관 기간 안에 남아 있는 메시지 표시 | 보관 기간이 지나 삭제된 메시지 복구 |

메일은 도착 시점부터 최대 24시간 저장되고 이후 예약된 정리 작업으로 삭제됩니다. 직접 링크를 다시 열어도 기존 메일의 도착 시각은 바뀌지 않습니다. 예를 들어 23시간 전에 도착한 메일은 지금 새 세션을 시작하더라도 곧 삭제될 수 있습니다.

따라서 링크는 정상인데 받은편지함이 비어 있을 수 있습니다. 최근에 새 메일이 없었거나, 발신자가 다른 주소를 사용했거나, 오타가 있었거나, 이전 메일이 이미 정리되었을 수 있습니다. 빈 화면만으로 링크가 고장 났다고 판단해서는 안 됩니다.

### 저장 방법에 따른 노출 위험 비교

다시 열기 위해 링크를 저장할 때는 편리함뿐 아니라 노출 범위를 함께 살펴야 합니다.

- 원래 탭을 계속 열어 두는 방법은 간단하지만 브라우저 종료나 충돌에 취약합니다.
- 개인 브라우저의 임시 북마크는 편리하지만 동기화 기능을 통해 다른 기기로 복사될 수 있습니다.
- 비밀번호 관리자의 보안 메모는 통제하기 좋지만 작업이 끝난 뒤 삭제해야 합니다.
- 암호화된 프로젝트 메모는 권한이 있는 소규모 테스트팀에 사용할 수 있으나, 메모 공유는 받은편지함 접근 공유와 같습니다.
- 스크린샷은 사진 백업, 메신저, 화면 공유, 방송 영상에서 유출될 수 있습니다.
- 공개 이슈, 소스 코드 저장소, 공개 위키, 고객 지원 티켓, 분석 로그에는 링크를 넣으면 안 됩니다.
- 브라우저 기록만 믿으면 기록 삭제나 동기화 때문에 재접근이 불안정하고 다른 사용자에게 노출될 수 있습니다.

짧은 개인 작업이라면 신뢰하는 브라우저 프로필에 임시 북마크를 만들 수 있습니다. 북마크 제목에는 전체 이메일 주소 대신 “자료 확인”처럼 일반적인 작업명을 사용하세요. 브라우저 동기화가 켜져 있다면 같은 계정으로 로그인한 가족 공용 기기나 업무 기기에도 URL이 전송되는지 확인해야 합니다.

### 전체 주소를 단기 자격 증명처럼 취급하기

cleanorapi.com의 직접 링크에는 이메일 주소와 별도의 비밀번호나 비밀 토큰이 없습니다. 그러므로 전체 주소는 단순한 메일 목적지이면서 받은편지함을 여는 단서이기도 합니다. 공개 게시물, 영상, 데모 화면, 오류 로그, 분석 이벤트, 공개 저장소에 노출하지 마세요.

비밀번호, 신분증, 의료 정보, 개인 키, 고객 데이터, 장기간 유효한 복구 코드 등을 임시 받은편지함으로 받지 않는 것이 안전합니다. 동료에게 메일 한 통의 정보만 전달해야 한다면 받은편지함 전체 링크를 넘기기보다, 허용된 범위의 필요한 정보만 보호된 채널로 공유하는 편이 낫습니다.

정상적인 품질 보증 테스트에서 팀이 링크를 공유해야 한다면 접근 허용자, 사용 종료 시각, 삭제 담당자를 미리 정하세요. 링크가 한 번 공유된 뒤에는 개인만 볼 수 있는 비밀 사서함으로 간주할 수 없습니다.

### 같은 기기에서 다시 여는 안전한 순서

짧은 개인 작업이라면 다음 절차를 권장합니다.

1. cleanorapi.com 화면에서 전체 주소를 직접 복사합니다.
2. 직접 링크를 한 번 열고 표시된 주소가 저장하려는 주소와 정확히 같은지 확인합니다.
3. 나중에 돌아와야 할 때만 통제된 위치에 임시로 저장합니다.
4. 신뢰할 수 있는 동일한 브라우저 프로필을 사용합니다.
5. 작업 중 다른 임시 받은편지함의 직접 링크를 열지 않습니다.
6. 확인, 다운로드, 테스트를 보관 시간 안에 완료합니다.

### 다른 기기에서 다시 여는 경우

같은 URL을 두 번째 기기에서 열면 그 기기의 새 세션에 주소를 등록할 수 있습니다. 가능하다고 해서 항상 바람직한 것은 아닙니다. 공용 PC, 도서관 단말기, 알 수 없는 확장 프로그램이 설치된 브라우저에서는 URL 흔적이 더 넓게 남습니다.

기기 전환이 꼭 필요하다면 공개 단체 채팅이나 평문 문서 대신 종단간 보호 채널 또는 안전한 메모로 링크를 옮기세요. 신뢰할 수 있는 개인 프로필에서만 열고 주소를 확인한 다음 저장한 복사본을 삭제합니다. 두 번째 기기에서 삭제해도 첫 번째 기기의 기록이나 동기화된 북마크가 자동으로 사라지지는 않으므로 각 위치를 따로 점검해야 합니다.

### “Not Found”와 빈 받은편지함 점검

“Not Found”가 나오면 먼저 `@` 기호, 전체 주소, 도메인 철자를 확인하세요. 도메인은 현재 지원되는 수신 도메인이어야 하며, 예약 이름과 잘못된 형식은 거부됩니다. 기억에 의존해 마침표, 하이픈, 밑줄 또는 다른 문자를 임의로 바꾸지 마세요.

페이지는 열리지만 예상 메일이 없다면 다음 순서로 확인합니다.

1. 저장한 주소와 현재 표시된 주소를 문자 단위로 비교합니다.
2. 다른 직접 링크를 열어 현재 세션 주소가 교체되지 않았는지 확인합니다.
3. 발신자가 실제로 같은 주소를 입력했는지 확인합니다.
4. 한 번 새로고침하고 정상적인 전송 시간을 기다립니다.
5. 메일 도착 후 24시간이 지났는지 살펴봅니다.
6. 기존 메일을 안전하게 대체할 수 있을 때만 한 번 재전송을 요청합니다.
7. 상대 서비스가 임시 도메인을 허용하지 않는다면 주소를 반복 생성해 정책을 우회하지 않습니다.

짧은 시간에 인증 메일을 여러 번 요청하면 이전 링크가 무효화되는 서비스도 있습니다. 하나의 정확한 주소를 사용하고 마지막으로 명시적으로 요청한 메시지를 기준으로 처리하세요.

### 세션의 24시간과 메일의 24시간은 별도입니다

브라우저 세션의 24시간과 각 수신 메일이 최대 24시간 보관되는 규칙은 서로 독립적으로 계산됩니다. 오늘 직접 링크를 다시 열면 세션 접근 기간은 새로 시작할 수 있지만 어제 도착한 메일의 나이는 초기화되지 않습니다.

매일 링크를 방문한다고 해서 백업이 만들어지는 것도 아닙니다. 직접 링크는 보관 서비스, 전달 기능, 영구 사서함, 미래 계정 복구 보장이 아닙니다. 필요한 작업은 시간 안에 끝내고, 합법적으로 장기 보존해야 할 기록은 적절한 저장소로 옮겨야 합니다.

다음과 같은 변화가 보이면 임시 주소 사용을 끝낼 시점입니다.

- 커뮤니티 계정에 평판, 비공개 메시지, 프로젝트 권한이 쌓입니다.

- 쇼핑 계정에 주문, 반품, 보증, 결제 기록이 생깁니다.

목적을 달성하면 임시 북마크, 비밀번호 관리자 메모, 프로젝트 문서의 URL을 제거합니다. 필요하면 제3자 서비스에서 로그아웃하고, 불필요한 동의 철회와 체험 구독 취소는 해당 서비스의 공식 메뉴에서 수행합니다. 북마크 삭제만으로 계정, 구독, 업로드 자료가 삭제되지는 않습니다.

- 결제, 신원, 복구, 장기 사용 가치가 생기면 영구 주소로 이전합니다.
- 작업이 끝난 후 저장된 접근 경로를 삭제합니다.

URL 형식과 검증 방식은 [이메일 주소 링크로 임시 받은편지함 바로 열기](/ko/blog/direct-email-inbox-link)에서 확인할 수 있습니다. 별도의 보관 제한은 [24시간 임시 이메일 안내](/ko/temporary-email-24-hours)를 참고하세요.

### 결론

전체 이메일 주소를 공유 가능한 단기 접근 정보로 취급할 수 있고, 보관 기간이 지난 메일의 소실을 받아들일 수 있을 때만 임시 받은편지함을 다시 여세요. 직접 링크는 비공개로 저장하고, 신뢰할 수 있는 브라우저에서 사용하며, 표시된 주소를 항상 정확히 비교해야 합니다.

직접 링크는 짧고 위험이 낮은 작업을 편리하게 해 주는 기능입니다. 소유권 증명, 영구 계정, 메일 보관소는 아닙니다. 현재 작업 이후에도 접근이 중요해지는 순간에는 비밀번호와 복구 옵션을 갖춘 장기 이메일 주소로 옮기는 것이 가장 안전합니다.
